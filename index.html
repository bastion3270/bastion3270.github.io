Secure TN3270 access to the mainframe

bastion3270 is a TN3270 / TN3270E web gateway and desktop 3270 emulator for IBM z/OS. Users work in a browser tab; the 3270 session runs in the gateway, so passwords typed into hidden fields never reach their device.

Closing the gaps TN3270 leaves open

Hidden fields stay hidden

The gateway runs the session and sends the browser a masked screen. A password typed into the page is not shown, copied, printed or kept there. Protected and numeric fields are enforced in the gateway, not trusted to the client.

TLS that actually connects

Host certificates are checked against the operating system's and your own certificate authorities, with the name rules z/OS certificates need, so encryption is not switched off just because a bank's CA was not deployed.

The gateway decides where sessions go

Users pick an administrator's profile or define their own connection, checked against a policy: an allow-list of hosts, required TLS, or none at all. Every session is audited.

A hostile data stream cannot take over

The 3270 protocol is parsed in memory-safe Rust without unsafe code, fuzzed and property-tested. A malformed packet ends with an error, never with a crash.

How it works

TN3270E over TLS ⇄
IBM z/OS VTAM · TSO · ISPF · CICS
  • Browser → gateway: keys, pasted text, cursor moves and function keys, checked against the field attributes as a terminal would.
  • Gateway → browser: the screen with every non-display field blanked, the status line and messages.
  • Gateway → mainframe: TN3270E over TLS 1.2 / 1.3, with optional client certificates (mutual TLS).

Two products, one secure core

Web gateway

Runs the 3270 sessions in the data centre and serves them to a thin browser client. Nothing to install on workstations.

  • Several sessions in tabs; survives a reload or a network drop
  • Copy, paste and print following the policy of each system
  • x3270 or IBM Personal Communications key layout, colour themes
  • Installable as an application from the browser
  • Thousands of sessions per process, denial-of-service limits
  • JSON audit log, Prometheus metrics, health and readiness probes
  • One static binary, non-root container image, Kubernetes manifests

Desktop client

The same core in a native window for Windows, macOS and Linux, with the same look and behaviour on each.

  • One small program, no runtime to install
  • Profiles that can be shared by a team
  • A clear dialog when a host certificate is not trusted

Terminal

  • TN3270 and TN3270E
  • Models 2–5 and custom sizes up to 62 × 160
  • Extended attributes and colours
  • SSCP-LU mode (VTAM logon screens)
  • 35 EBCDIC code pages
  • Behaviour follows x3270
  • English and Czech user interface

Try it in five minutes

You need Git and Podman with podman-compose, or Docker with Docker Compose. The stack runs the published gateway image and a local Hercules emulator with the free MVS 3.8j “TK4-” system — no mainframe needed.

git clone https://github.com/tom-danek/bastion3270.git
cd bastion3270
podman-compose -f docker/docker-compose.yml up -d
# or: docker compose -f docker/docker-compose.yml up -d
  1. Open http://127.0.0.1:8080. The client connects to Hercules MVS 3.8j (TK4-) at once.
  2. MVS needs about a minute to start. On the TK4- logo press Clear on the key bar under the screen.
  3. At Logon ===> type HERC01 and press Enter.
  4. Enter the password CUL8TR — it is not shown, and the gateway never sends it back to the page — then press Enter until the menu appears.

The user guide explains the screen and the keys.

Questions

What is TN3270?

TN3270 and its extension TN3270E are the Telnet-based protocols used to reach IBM mainframe applications such as TSO, ISPF and CICS through 3270 “green screen” terminals. A TN3270 emulator plays the role of the terminal.

Does it work with z/OS?

Yes. bastion3270 is built for IBM z/OS and is tested against the Hercules emulator with MVS 3.8j and with z/OS data streams in its regression tests.

Is it free?

Yes. bastion3270 is open source under the Apache License 2.0, including commercial use.

Is it ready for production?

It is pre-1.0. The protocol core, the web gateway and the desktop client are tested extensively, including load tests of thousands of sessions per gateway, but the configuration and the WebSocket protocol may still change between minor versions. See the changelog.

Who makes it?

bastion3270 is developed by one author in their spare time, together with an AI coding assistant. The author decides the design and reviews every change; all code follows the same standards: no unsafe, no panics in production code, behaviour that follows x3270 and the RFCs, and a regression test for every fix.

How do I report a bug or ask for a feature?

Open an issue on GitHub. Please report security problems privately, as described in the security policy.
